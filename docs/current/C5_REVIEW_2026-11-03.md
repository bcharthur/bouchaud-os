Preuve d'exécution same-SHA : `p13-cible-kvm.yml` (témoin historique rouge attendu, fenêtre corrigée verte, image livrée ×24, KVM SMP4) relancé sur `main@c1e55da` — voir `status.json` pour le résultat.

## Chemin

```text
#PF ring3 → peuple_a_la_demande
  ├─ jeton de mapping (VMA couvrant la page) lu sous Mm
  ├─ FaultPage (pml4, page, jeton) : Missing → Loading (un seul chargeur) ; les autres
  │   attendent sur la WaitQueue de l'enregistrement, puis relisent (Present ⇒ translate)
  └─ peuple_page_loader, Mm repris :
       pml4 inchangé ? sinon Retired · jeton inchangé ? sinon Retry · PTE déjà là ? Resolved
       ├─ Zero        : alloc_frame (mise à zéro) → map  (tout sous Mm)
       ├─ Framebuffer : map_foreign (pas d'allocation)
       ├─ SharedFile  : bail de page hors Mm → Mm repris, revalidation complète → map_foreign
       └─ File privé  : contenu construit HORS Mm dans un tampon → Mm repris, revalidation
                        → map_new_frame_accounted : alloc → copie → fence(Release) → PTE
                        (clean cache : acquire hors Mm → revalidation → map, sinon release)
```

## Invariants exigés et preuve

| Invariant | Argument |
|---|---|
| Aucune PTE visible avant initialisation | File : copie puis `fence(Release)` puis PTE (P13_PAGE_REMPLIE_AVANT_PUBLICATION_V1, banc négatif `banc-c5-ordre-historique`). Zero : mise à zéro dans `alloc_frame` avant `map`. x86 TSO conserve l'ordre des écritures pour les autres cœurs et le parcours de tables. |
| Aucune frame doublement rendue | `free_frame` vérifie le bitmap (`marque_libre`, assertion « double free »), y compris en lot. Les frames d'un espace sont possédées par `pages` ; `map_new_frame_accounted` ne rend la frame que si elle n'a jamais été publiée. |
| Aucun UAF | La frame n'est rendue qu'au retrait de sa PTE (munmap avec invalidation/ACK) ou à la destruction de l'espace. Un chargeur dont le jeton ou le pml4 a changé ne publie rien (Retry/Retired) et ne possède aucune frame à ce moment (allocation sous Mm, après revalidation). |
| Aucun mapping partiellement initialisé | Le contenu est complet avant publication ; une E/S courte rend `IoError` sans publier. |
| Pas de course avec teardown | `retire_fault_range`/`forget_fault_space` publient l'état terminal pendant que l'enregistrement est encore trouvable (pas de second chargeur dans la fenêtre) ; le chargeur revalide pml4 + jeton sous Mm avant toute publication. |
| Fautes concurrentes même page | Un seul `Loading` par (pml4, page, jeton) ; un second arrivant attend ; une faute arrivant après l'oubli de l'enregistrement trouve la PTE (`translate`) et rend `Resolved` sans allouer. `map` refuse de remplacer une PTE présente différente. |
| TLB | Transitions non-présent → présent : pas de shootdown requis (x86 ne met pas en cache les entrées non présentes) ; `invlpg` local. Retraits : invalidation avec ACK (hors périmètre C5). |

## Remarques (non bloquantes, aucun code modifié)

- **C5-R1 (durcissement possible)** : la mise à zéro de `alloc_frame` n'a pas la `fence(Release)` explicite de `map_new_frame_accounted`. Le réordonnancement par le compilateur exigerait de prouver l'absence d'alias entre deux pointeurs issus d'entiers, ce qu'il ne fait pas, et `flush` (asm) suit la PTE. Non démontré ; une `compiler_fence` rendrait l'invariant structurel pour tous les appelants (y compris les tables intermédiaires allouées par `entry_mut`).
- **C5-R2** : `map_alloc_accounted` garde dans `pages` une frame dont la publication a échoué (OOM de table intermédiaire) jusqu'à la destruction de l'espace. Fuite bornée à la durée du processus, pas un double free ni un UAF.

Rouvrir C5 exige un contre-exemple exécuté (journal + image identifiée), pas une intuition.
