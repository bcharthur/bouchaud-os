## Candidat

Deux scans (`wake_sleepers`, `borne_interactive_a_jour`) reutilisent leur
vue du registre au lieu d'acquerir/lacher un garde imbrique par emplacement.
Le temporaire de `for ... tasks().len()` detenait deja un garde pendant
toute la boucle : la portee de protection ne change pas et le garde tombe
avant les alarmes. Aucune echeance, priorite, demande ou regle de notification
n'est modifiee. Cela supprime un cout reel ; son role dans P2 reste a mesurer.

`reveil-precis cout on|off` active explicitement le profilage. Par defaut,
il est OFF. Les lectures MSR mesurees sont les appels existants a read_msr ;
aucune relecture du timer n'est ajoutee. Les ecritures deadline et toutes
les ecritures MSR sont mesurees separement. Les scans, publications,
rearmements et envois IPI distants sont chronometres ; les prises du registre,
appels a cpu::rdtsc et demandes differees sont comptes. Il n'existe pas
d'envoi IPI local dans reschedule_cpu. Le profilage utilise deux lectures
TSC serialisees supplementaires par mesure, non incluses dans rdtsc_appels.
Les cycles sont INCLUSIFS (ne pas additionner les sites imbriques), peuvent
inclure un retrait du vCPU et incluent le cout du profileur. Le temps IRQ
s'arrete AVANT dispatch pour ne pas compter la suspension d'une pile IRQ.
Les maxima cumulatifs ne se soustraient pas ; seuls appels/cycles se pretent
aux differences entre releves.

Les boots de diagnostic sont distincts des quatre paires A/B sans profilage.
Ils portent `DIAGNOSTIC_SEULEMENT ne_qualifie_pas_P13=1`. Le workflow canonique
passe `p13_strict=true` sur la branche d'audit ; cela ne prouve pas que son
runner GitHub repond au contrat d'hote dedie des trois campagnes finales.
Aucun seuil, quorum, filtre de contamination ou verdict n'est modifie.
