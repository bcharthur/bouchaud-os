P0 — BKL / resume_after_schedule
================================
Le parking actuel fonctionne, mais chaque libération du BKL réveille tous les
CPU garés. Les mesures du run Google montrent alors beaucoup de wake IPIs et de
réveils sans acquisition, alors qu'un BKL n'a qu'un seul gagnant possible.

Le correctif :
  - garde le protocole SeqCst anti-lost-wakeup existant ;
  - ne modifie ni OWNER ni DEPTH ni la logique de migration ;
  - réveille exactement UN CPU garé par libération ;
  - choisit la cible en round-robin pour éviter un biais permanent ;
  - conserve le court spin actif et le fallback IRQ masquées existants.

La vivacité reste assurée : si le CPU réveillé perd la course, c'est qu'un autre
CPU a acquis le BKL ; ce nouveau propriétaire réveillera à son tour un waiter
lors de sa libération. Si personne n'a acquis le verrou, le waiter voit FREE et
ne peut pas se rendormir sur cet état.

P1 — fsync / persistance
========================
La V1 évitait déjà de réécrire le contenu des fichiers inchangés, mais chaque
fsync réécrivait encore les 1024 secteurs réservés à la table, soit 512 Kio de
PIO sous le BKL.

Le correctif :
  - conserve le format disque et SECTEUR_CONTENU = 1025 ;
  - conserve 1024 secteurs réservés, donc compatibilité avec les images V1 ;
  - lit et écrit uniquement le préfixe de table réellement utilisé ;
  - 8 fichiers = 4 secteurs de table au lieu de 1024 ;
  - l'en-tête reste écrit en dernier ;
  - l'empreinte DISQUE et tous les chemins d'échec restent inchangés dans leur
    principe.

Ce que ce paquet NE change PAS
==============================
La readiness de poll reste une WaitQueue globale avec wake_all. La remplacer
naïvement par wake_one serait incorrect : on pourrait réveiller un poller qui
ne surveille pas l'objet devenu prêt et laisser le bon poller endormi.
Le vrai P1 suivant, si les mesures le justifient encore, sera une readiness
ciblée par objet / groupe de descripteurs.
